## facts
- Megatext renders oversized text (characters larger than 8×8 pixels) by drawing the glyphs directly into a bitmap and positioning them at desired screen coordinates.
- No special VIC-II trick is required; the "mode" is simply standard bitmap display (SBM or MCBM) with the bitmap pre-filled with large-font character shapes.
- Character shapes are typically generated by a tool or hand-crafted in a bitmap editor and stored as binary data.
- Introduced July 2004.

## sequence

1. Enable bitmap mode: `$D011` = `$3B` (BMM=1); `$D016` = `$C8` (SBM hires) or `$D8` (MCBM multicolor).
2. Clear bitmap (8000 bytes at bitmap base).
3. For each character to display: copy pre-rendered glyph data (scaled-up font pixels) into the bitmap at the correct byte offset.
   - Byte offset for column c, row r (hires): `(r * 40 + c) * 8 + pixel_row`
4. Set screen RAM color bytes: high nibble = foreground color, low nibble = background color, per 8×8 cell.
5. Set `$D021` for global background if needed.
6. No raster IRQ required; static display.

## lookup

| bitmap cell offset | formula (SBM) | notes |
|---|---|---|
| Column c, char row r, pixel row p | `(r * 40 + c) * 8 + p` | p = 0–7 (top to bottom within cell) |

## constraints
- Large glyphs span multiple 8×8 bitmap cells; each cell can have only 2 colors (SBM) or 4 colors (MCBM).
- Color changes within a glyph are limited by the bitmap mode's per-cell color constraints; large single-color glyphs are straightforward, multi-color large glyphs require careful cell color assignment.
- No VIC-II trick limits apply; this is purely a software rendering / data layout technique.
