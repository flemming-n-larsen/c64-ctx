## facts
- The C64 uses a **MOS 6510**, not a plain 6502. The 6510 is a 6502-family derivative with an integrated 8-bit I/O port.
- Instruction set is fully 6502-compatible: same 151 documented opcodes, same illegal opcodes, same cycle timing.
- Clock speed: PAL ~0.985 MHz, NTSC ~1.023 MHz.
- Later C64 revisions (C64C) use the **8500**, the HMOS shrink of the 6510 — electrically and software identical.
- The 6510 has a tri-state address bus enable pin used during DMA (VIC-II steals cycles); code does not control this directly.

## 6510-vs-6502 differences

| feature | plain 6502 | MOS 6510 in C64 |
|---|---|---|
| On-chip I/O port | none | `$0000` DDR, `$0001` data — drives LORAM/HIRAM/CHAREN and cassette lines |
| Tri-state bus | no | yes — VIC-II steals cycles by asserting bus enable |
| Instruction set | 6502 documented + undocumented | identical |
| Clock | varies by system | PAL 0.985 MHz / NTSC 1.023 MHz |

## io-port
- `$0000` (`D6510`): data direction register — bit `1` = output, bit `0` = input.
- `$0001` (`R6510`): I/O data — controls memory banking and cassette interface.
- Default power-on state: DDR `$2F` (bits 0,1,2,3,5 = output), port `$37` (LORAM=1, HIRAM=1, CHAREN=1, motor off).
- MUST set direction bits in `$0000` before writing to `$0001`; uninitialised direction bits leave port lines floating.

## constraints
- Agents MUST refer to the CPU as the **6510** when describing C64-specific behavior (I/O port, banking, DMA).
- Agents SHOULD use **6502** when describing the instruction set, addressing modes, or opcode behavior — these are family-scoped facts.
- Code that touches `$0001` MUST read-modify-write to avoid clobbering unrelated port bits (cassette lines).
- `$0000` and `$0001` occupy zero-page addresses; they are NOT general-purpose RAM and MUST NOT be used as variables.
