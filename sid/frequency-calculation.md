## facts
- SID pitch programming is a two-step conversion: note distance → frequency in Hz, then frequency in Hz → 16-bit SID register value.
- Codebase64 gives the standard equal-temperament note formula as `FREQ_HZ = BASEFREQ * 2^(NOTE / STEPS_PER_OCTAVE)`.
- The SID register formula is `SID_FREQ = FREQ_HZ * 256^3 / PHI`, where `PHI` is the machine clock for the target C64 model.
- PAL and NTSC need different constants, so a table tuned on PAL will play sharp on NTSC if you reuse the same register values unchanged.

## formulas
```text
BASEFREQ = 440
NOTE = semitone distance from the reference note
STEPS_PER_OCTAVE = 12

FREQ_HZ = BASEFREQ * 2^(NOTE / STEPS_PER_OCTAVE)

SID_FREQ = FREQ_HZ * 256^3 / PHI
```

## machine constants
| machine | `PHI` / constant | notes |
|---|---|---|
| PAL C64 | `985248` | Standard PAL A440 tables use this clock |
| NTSC C64 (`6567R8`) | `1022727` | Common NTSC table constant from Codebase64 |
| NTSC C64 (`6567R56A`) | different | Needs its own constant; `6567R8` tables are only approximate |
| PAL-N / Drean | different | Requires recalculation for accurate tuning |

## worked example
- For PAL A4 = `440 Hz`, Codebase64 gives `SID_FREQ = 17.02841924 * 440 = 7493`, which is `$1D45` in hex.
- Octaves are exact powers of two, so once you have one octave, higher/lower octaves can be generated by shifting the register value left/right by one bit per octave.

## constraints
- A music table is machine-specific: PAL, common NTSC, early NTSC, and PAL-N/Drean should not share one "accurate" tuning table.
- Fine-tuning tables and micro-steps should be generated from the formula, not by interpolating hex values by eye.
- When memory matters, precompute one octave and derive the rest by shifts only if your note layout preserves the same tuning basis.
